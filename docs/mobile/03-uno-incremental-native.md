# Jot Android 方案三：Uno 渐进迁移与平台编辑器

文档版本：1.0｜编制日期：2026-10-16｜代码基线：`6d019b3`、Jot 1.2.1

本文是独立技术与交付方案，尚未执行迁移或真机验证。首发 Android，现有 Windows 版继续发布。方案目标是复用经过验证的 WinUI 页面结构和 C# 业务，保留各端必要的平台实现。

## 1. 路线定义与选择理由

新建 Uno 工程，Android 明确选择 Native renderer，Windows 继续使用 WinAppSDK/WinUI。对列表、日历、设置和部分统计逐页迁移；对编辑器、声音、外部文件、生命周期提供平台实现。

此路线与“Uno Skia 统一界面重构”的区别是：优先维护现有页面和产品行为，不以更换整个视觉系统为目标；Android 的原生输入能力优先，Windows 不切换到 Skia Desktop。

Uno 当前模板默认采用 Skia，创建项目时必须显式选择和核验 Native renderer，不能依据旧模板记忆推断配置。WinAppSDK 目标使用微软的 WinUI 实现，与 Android Uno 目标具有不同运行边界。[Uno 工作方式](https://platform.uno/docs/articles/how-uno-works.html)、[渲染器说明](https://platform.uno/docs/articles/features/using-skia-rendering.html)

建议以 .NET 10 与已发布 Uno 6.7 系列作为技术验证候选，实际选定补丁、SDK 和依赖版本写入锁定文件；Uno 工具或扩展的可选商业授权单独评估，不将其视为运行应用的默认必要条件。[Uno 6.7 发布说明](https://platform.uno/blog/uno-platform-6-7/)

适用前提：团队熟悉 WinUI/XAML，重视保留现有交互资产，愿意维护兼容性清单。若主要页面在试迁移后出现大量无法隔离的 API 缺口，或框架升级经常造成双平台回归，应重新考虑 MAUI 原生路线，而不是无限增加条件编译。

路径相对仓库根目录，当前只有 Windows 工程，没有独立 Core、Android 项目和设备间同步实现。

## 3. 商用功能范围和手机界面

| 版本范围 | 交付内容 |
|---|---|
| 1.0 必需 | 今日与历史写作、时间戳、撤销/恢复、保存状态、列表与全文搜索、月历 |
| 1.0 必需 | JSON/Markdown/TXT/ZIP 导入、冲突处理、导出、完整备份恢复、Trash 管理 |
| 1.0 必需 | 主题、字号、基础统计、保存音、可选触感、无障碍、隐私和支持页 |
| 1.1 可延后 | 全年展示、词云细节、高级正则工作台、全部声音主题、复杂动画 |
| 独立扩展 | 自动同步、账户、购买权益、iOS、附件和新 Windows 产品形态 |

手机导航采用四入口，原桌面六个模块通过“更多”组织；不把 64px 桌面导航岛缩小后直接投放。编辑器优先占据可用高度，工具栏在软键盘上方或安全区内。单日阅读中的侧边小日历改为日期选择弹层；导入并排对照改为分页切换；词云同时提供词频列表。

字号和系统缩放要共同生效；360dp 宽、大字体、横屏、手势返回均不得遮挡保存和恢复入口。触摸区域建议不小于 48dp，热图用数值补充颜色。页面需要完整的空、加载、失败、权限丢失、取消、恢复中状态。

现有桌面功能保持独立验收。共享页面调整不能以“Android 上可用”为理由破坏桌面快捷键、窗口材质、导航和阅读。Windows 特有能力留在平台层，不以手机能力最低值统一削弱所有端。

## 4. 工程组织和源码共享策略

```text
Jot.Domain / Jot.Application / Jot.Infrastructure
              ↑                         ↑
       Jot.Windows                 Jot.Uno.Android
       WinAppSDK                   Uno Native renderer
              ↑                         ↑
           经过筛选的共享 XAML / Presenter 源码
           Windows 与 Android 分别编译并验证
```

现有根目录 `Journal.csproj` 使用 SDK 默认文件包含规则。实施时先将新增工程目录从旧工程编译/XAML 发现范围排除，或在独立提交中迁移旧工程目录；禁止直接在根目录下增加大量 C# 文件，导致桌面工程把新项目源文件再次编译。

先建立纯 C# 核心和新的 Uno 项目，旧 Windows 生产工程维持发布；新共享页面通过受控的源文件链接或 Uno 兼容类库逐页引入。引用 Windows-only UI 程序集不等于源码共享，UI 类库必须按目标框架和渲染器构建。对同一 XAML 建立唯一编译归属，避免重复生成类型和资源。

共享范围分三层：

1. **领域与用例共享**：日期、摘要、导入规则、修订和备份协议，不引用 Microsoft.UI 或 Android 类型。
2. **呈现源码共享**：页面结构、绑定、有限的 Presenter；在两个目标下单独编译，外观对象只在这一层出现。
3. **平台实现独立**：编辑器、文件选择、音频、窗口、字体、生命周期、原生图标和返回处理。

保留 CommunityToolkit.Mvvm，不在迁移同时强制换成 MVUX。现有单例通过门面逐步转向注入。`DataChanged` 携带受影响日期/修订，由呈现层分发到 UI 线程，不能让 SQLite 服务捕获某个页面的 DispatcherQueue。

核心可先用不含 Windows 限定的 net8.0 兼容旧桌面，再安排桌面框架升级以统一目标；每个阶段记录临时兼容层和移除期限。Android 工程使用当前受支持的 .NET/Uno 组合，不继承 `win-*` RuntimeIdentifier 或 Windows SDK 包。

## 5. 平台编辑器实现路径

定义 `IJournalEditorHost`，能力为加载文本、读取当前会话快照、读取/设置选区、插入文本、撤销重做、通知组合输入结束、调整字体和请求焦点。领域模型只看文本与编辑序号，不看 RichEditBox、EditText 或 TextBox 类型。

Windows 适配器包裹现有 RichEditBox。Android 首选 Uno 多行 TextBox，在 G0 中验证选区、组合输入、粘贴和大文本；需要底层能力时使用封装的 Android EditText。不要通过大量页面代码探索模板内部子节点，所有这种适配集中在一处并有版本回归用例。

Uno Native renderer 支持将原生控件纳入视图树；实际封装按照所锁定版本的文档和模板编译验证，不把示例里的旧命名空间直接视为当前可用 API。[原生视图集成](https://platform.uno/docs/articles/native-views.html)

文本变更必须区分用户输入、载入旧内容、撤销和外部刷新。用户输入期间不双向反复整段 SetText；组合输入提交前不强制替换选区。时间戳作为一个事务插入，快速换日必须先冻结旧会话。

当前桌面的撤销保存全文快照并最多 200 步；手机版应按编辑事务合并并限制内存预算，不能用固定步数掩盖长文内存。优先让一个编辑器层拥有历史，应用层只维护恢复草稿。大于已测阈值的正文完整保留，允许简化阅读或编辑，不静默截断。

软键盘不能依赖每个键的 KeyEvent。语音、候选词点击和输入法粘贴可能走不同路径；音效依据已提交文本及明确动作。Uno TextBox 的粘贴事件覆盖也有平台差异，因此正确性应以最终文本变更和会话状态为依据。[TextBox 说明](https://platform.uno/docs/articles/controls/TextBox.html)、[Android KeyEvent](https://developer.android.com/reference/android/view/KeyEvent)

## 6. 兼容性台账和逐页迁移方法

每一个 Uno 编译告警或运行差异均进入台账，字段包括源码位置、API、目标系统、复现条件、用户影响、替代实现、责任人和验收用例。迁移指导只能提供方向，不能作为“99% 可复用”的项目承诺。[Uno 迁移指导](https://platform.uno/docs/articles/howto-migrate-existing-code.html)

| 类别 | 示例 | 默认处理 |
|---|---|---|
| 直接候选 | 普通 Grid、文本、绑定、ObservableCollection | 移入后测量、滚动、更新和无障碍验证 |
| 行为差异 | Popup、Focus、Loaded/Unloaded、TextBox、滚动嵌套 | 平台适配或缩小使用范围 |
| Windows 专属 | hwnd、user32、comctl32、Mica、注册表 | 隔离在 Windows，不进入共享依赖 |
| 已知缺失 | 编辑器依赖的 RichEditBox Document/IME 成员 | 平台编辑器替换 |
| 性能敏感 | 全年日历、词云、自定义 Panel、动态字体 | 先保留算法，测量后决定复用布局或重写 |

每页按“业务用例固定—UI API 盘点—Android 编译—实际操作—Windows 回归—合入”执行。列表页先迁移，随后月历、设置、阅读、导入和统计；编辑器作为独立主线在 G0 就启动，不能排到最后。

自定义 Panel 需要重新验证 Measure/Arrange、无限高度、嵌套滚动、字体回退、实际触摸命中和缩放。源代码中已有自适应规则只证明 Windows 上存在布局处理，不证明手机体验合格。对共享库中成片条件编译设定审查：同一页面若多数核心交互分叉，拆为两个页面共享用例，比继续堆积条件更可维护。

## 7. 数据与保存一致性

正文继续使用 `Journals/yyyy/MM/yyyy-MM-dd.md`，以日记日期作为逻辑键。用户选择的历史日期不随 UTC 转换改变；修改时间另存 UTC。新增修订 ID、父修订、内容哈希和 schema 版本，跨设备格式只存相对路径。

建立两类本地库：可重建索引与持久状态。持久状态保存草稿、编辑序号、基线、未完成提交和导入操作日志，清缓存不得删除。默认保存到应用私有目录，外部目录用于显式交换与备份。

修订信息保存在持久状态或版本化旁车文件，并包含在正式备份中；索引重建不改变修订。内容哈希针对实际保存字节，导入规范化行为明确记录。所有平台的保存、导入和恢复共用按日串行写入协调器，在同一个临界区完成基线检查与提交；不同入口不得绕开仓库直接写正文。

列表使用日期游标分页，初始每批 50 条；搜索取消旧查询并按查询序号应用结果。增量搜索缓存以正文哈希为更新依据；FTS 仅在目标 SQLite 支持且中文召回验证通过后启用。统计按变更日期更新，词云结果缓存到对应修订集合，不在每次导航时全量载入所有正文。首次索引重建提供进度和取消，不能伪装成空日记库。

保存用例先固定日期/内容/版本快照并持久化草稿，再检查基线、建立旧正文恢复点、同卷临时写入与刷新、替换正文、更新索引和标记完成。崩溃后按操作状态和哈希恢复，不能把文件写入和 SQLite 事务混为一个原子动作。

UI 只在提交序号仍是当前序号时清除未保存标记。不同日期的会话相互隔离；迟到回调不能改变新日期的“已保存”。原内容被清空属于真实编辑，需保存空文档或明确删除，不沿用空内容直接清除脏标记的做法。

草稿可从 300～500ms 防抖开始调优，正式正文约 1.2s；切后台补充尝试提交，但 Android 不保证退出回调发生。承诺范围是已经确认持久化的文本，不含尚在输入法候选区或尚未落盘的输入。[生命周期依据](https://developer.android.com/guide/components/activities/process-lifecycle)

备份与回收站按时间和容量管理，恢复依赖的版本不能被清理。存储服务明确返回磁盘满、权限、冲突、正文成功但索引待修复等结果，不捕获异常后仍向上层报告成功。索引可重建，正文与草稿故障不得通过“重置应用”掩盖。

## 8. Android 文件、音频、字体及隐私

文件选择采用系统文档选择器和 URI 流。导入解析不接触窗口句柄；若用户选择长期备份目录，持久授权失效后提供重新选择和本地导出，不能默默停止保护。不同文档提供者的 rename/replace 能力不同，首版不把外部树当作高频自动保存目录。[SAF](https://developer.android.com/training/data-storage/shared/documents-files)

音频使用 Android SoundPool，复用短 WAV，预加载当前主题并在离开前台时释放或暂停。声音生成写缓存或构建资源，不写安装目录。触感单独实现与配置。默认系统字体，附加字体经过授权并测试字体回退；不迁移 Windows 注册表字体扫描。[SoundPool](https://developer.android.com/reference/android/media/SoundPool)

应用内快照不能抵御卸载，必须交付外部备份恢复。默认无账户、无业务网络请求；诊断为用户选择，不能记录日记正文、标题、搜索词或导入文件名。云备份与设备迁移规则显式定义，避免 OS 默认行为与“本地优先”的说明冲突。[私有文件生命周期](https://developer.android.com/training/data-storage/app-specific)、[系统备份](https://developer.android.com/identity/data/autobackup)

应用锁只限制打开界面，不等于正文加密。如果要增加加密库，必须涵盖正文、索引摘要、草稿、历史、临时文件和外部备份，并验证密钥丢失与恢复。商业版的隐私声明、权限说明和支持流程应对应实际行为，不能写尚未实现的保护能力。

## 9. 导入、恢复与设备互通

保留 MD/TXT/JSON/ZIP 格式、日期识别和冲突策略。复用当前 20MB 单文件、100MB 解包总量初始限额，增加真实解压计数、条目数、超时和取消。文件扩展名不代表内容可信；ZIP 路径、重复日期、损坏编码和未知 JSON 版本需明确错误结果。

备份采用带 manifest、格式版本、文件哈希的 ZIP，保留正文原样或提供明确的规范化模式。现有 ExportService 的 Trim 行为不能用于“逐字节原样备份”承诺。恢复先暂存和校验，再预览并提交，过程中保留原库和恢复日志；取消不导致全库半空。

桌面导出的正文在 Android 导入后重建索引，反向同理。用多语言、历史日期、同日重复、首尾空行、时区变化和超长内容验证往返。

自动同步不属于 Uno 提供的现成功能。后续增加持久操作队列、设备 ID、修订/基线、幂等键、删除墓碑和冲突副本；不能仅按 LastModified 大小覆盖，也不能把导入的 MergeAppend 当成可靠双向同步。SQLite 各端独立，正文及版本信息通过传输适配器交换。服务端、账号、密钥与运维另外预算。

## 11. 测试矩阵与验收指标

Android 产品支持基线暂定 Android 10 及以上，最终由 G0 验证用户覆盖和组件支持后冻结。至少覆盖中低端 4GB ARM64 真机、两家 OEM、不同 Android 版本、Gboard 与中文输入法；Windows 覆盖当前声明支持的系统、缩放和键盘行为。

| 类别 | 商用门槛 |
|---|---|
| 核心一致性 | 日期、字数、摘要、导入分段与旧版约定一致，差异有明确迁移说明 |
| 输入 | 候选词、语音、Emoji、长按粘贴、外接键盘、撤销与光标恢复通过 |
| 保存 | 每个提交步骤模拟中断、磁盘满、旧会话迟到回调，确认数据可恢复 |
| UI 兼容 | 所有已使用 Uno API 已归类，发布路径不存在未处理的关键缺失成员 |
| 布局 | 360dp、横屏、200% 字号、TalkBack、键盘弹出、长文本无阻断 |
| 性能目标 | 参考机冷启动可编辑 P95≤3.5s；100KB 输入反馈 P95≤50ms；10000 篇热索引搜索 P95≤500ms |
| 恢复与升级 | 桌面双向交换、重复恢复、格式迁移失败重试、旧版升级均通过 |
| 长稳 | 页面切换 100 次、连续编辑 30 分钟、主题切换与音频暂停，无持续泄漏 |

以上为待测目标，保存数据集、设备型号、包版本与测量结果。先证明可靠性再调优启动速度，不能用全局吞异常或禁止诊断告警使测试看起来通过。

CI 分别构建 Windows 与 Android，执行共享核心测试、兼容台账检查、Release 打包、升级安装和真机冒烟。某平台通过不替代另一平台。任何共享 XAML/Presenter 修改触发双平台检查，纯 Android 代码仍需验证核心契约。

## 12. 发布治理、维护与交接

发行前固定正式应用 ID、签名、versionCode 和数据 schema；签名秘密保存在安全凭据系统。检查实际 APK/AAB 的运行时、SQLite、Uno 依赖中的原生库及 ARM64/16KB 兼容；提交前重新核验 target API 与渠道要求。[target API](https://developer.android.com/google/play/requirements/target-sdk)、[16KB 兼容](https://developer.android.com/guide/practices/page-sizes)

发行材料包含真实手机截图、权限用途、隐私行为、备份说明、支持入口和第三方许可。若启用收费，单独完成渠道购买、退款、恢复购买验证；付费权益不得阻止数据导出。商店审核等待和政策处理不算开发人日承诺。

先封闭测试再分批扩大；任何确认的数据损坏、恢复失败或跨日期错写立即停止扩大。为保存失败、导入失败、音效异常、平台控件异常设置脱敏错误码；没有用户授权不上传正文。连续观察期至少 7 天，并记录设备和使用样本数量。

框架补丁升级先在验证分支跑双平台控件、输入、恢复矩阵，再进入正式版。避免维护永久框架 fork；确需补丁时记录上游问题、维护责任和撤销条件。Android 回退采用更高 versionCode 修复版本，数据迁移提供恢复点，不依赖安装旧包。

最终交付必须含兼容性台账、共享/平台边界说明、安装包与符号、依赖锁、真机与 Windows 回归报告、备份格式、迁移及故障恢复手册、素材授权、发行记录和支持责任人。客服优先保护并导出用户数据，不将卸载或清空应用数据作为默认排障步骤。
