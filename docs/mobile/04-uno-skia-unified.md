# Jot Android 方案四：Uno Skia 统一界面与产品重构

文档版本：1.0｜编制日期：2026-10-16｜代码基线：`6d019b3`、Jot 1.2.1

本文是待实施的独立方案，未进行 Android 或 Skia 原型验证。先交付 Android 手机商用版，现有 Windows 版在过渡期继续使用；后续再决定是否发布基于 Skia Desktop 的新桌面客户端。

## 1. 产品与技术决策

以 Uno 的 Skia renderer 为移动端主要渲染方式，重新设计手机优先的 Jot 界面。抽取业务规则和数据层，建立可共享的设计系统、功能模块和测试契约。与渐进迁移方案相比，本方案优先解决长期一致性，不以尽量保留现有 XAML 文件为目标。

Uno 从 6.0 起在新模板中默认使用 Skia；它与 Native renderer 的运行边界不同，WinAppSDK 目标仍使用微软原生 WinUI。若未来希望 Windows 与 Android 都走 Skia，应评估 `net10.0-desktop` 路线，不能把原 WinAppSDK 工程改个开关就声称完成统一。[Skia 渲染器](https://platform.uno/docs/articles/features/using-skia-rendering.html)

技术验证以 .NET 10 和 Uno 6.7 系列为候选，锁定实际通过验证的版本。Skia 下的输入、屏幕阅读器、系统字号等能力持续演进，需用实际版本验证；不能根据发布说明推断自定义日历、词云和编辑器已经自动具备相同能力。[Uno 6.7](https://platform.uno/blog/uno-platform-6-7/)

本方案适合把 Jot 发展为多端产品、愿意投资统一视觉和组件、计划持续迭代的团队。对于仅想尽快获得手机日记本的个人维护者，MAUI 原生方案通常更经济。本路线需要明确产品设计与渲染性能责任人。

## 2. 现有资产如何使用

| 资产 | 使用方式 | 不可直接继承的假设 |
|---|---|---|
| Markdown 正文和年月目录 | 保留格式与一日一篇规则 | 不复制 Windows 绝对路径 |
| 日期识别、导入拆分、摘要、字数 | 抽取为纯 C# 算法 | 不将目前 UI 类型带入领域层 |
| SQLite 索引和统计 | 保留必要 schema/算法，增加修订与恢复设计 | 当前“同步”不是设备间同步 |
| 主题色板、声音主题、图标 | 转换为设计变量和资源清单 | Mica/Acrylic、注册表字体和 WinMM 不适用 Android |
| 日历、词云、自定义 Panel | 复用排布思路与规则，重新选择渲染实现 | 原 Measure/Arrange 行为与新渲染表现不保证一致 |
| WinUI 页面与 code-behind | 作为行为参考与回归样本 | 不作为必须保留的代码结构 |

源码依据包括 `Journal.csproj`、`Services/DiaryStorageService.cs`、`Services/DiaryIndexService.cs`、`Services/ImportService.cs`、`ViewModels/AnalyticsViewModel.cs`、`Models/DayHeatmapItem.cs` 和 `Views/EditorPage.xaml.cs`。当前路径以 `Journals/yyyy/MM/yyyy-MM-dd.md` 为准，README 的 Diaries 描述需在实施时统一。

现有 RichEditBox 核心成员在 Uno 兼容清单中仍存在缺口。本方案的编辑器采用明确适配边界，不建立在这些成员将自动补全的假设上。[RichEditBox 支持清单](https://platform.uno/docs/articles/implemented/microsoft-ui-xaml-controls-richeditbox.html)

## 3. 商用版本边界

Android 1.0 交付完整离线日记闭环：首次启动、导入旧数据、今日/历史编辑、时间戳、撤销、草稿恢复、列表搜索、月历、基础统计、主题字号、音效开关、回收站、备份恢复、隐私与支持页。

1.1 可交付统一词云、全年热图、高级导入、更多声音与主题。后续 Windows Skia、iOS、账号同步、附件、购买权益另行评审。统一架构不意味着这些平台已经完成适配，工期不应被一句“跨平台”省略。

| 用户流程 | 商用要求 |
|---|---|
| 第一次写作 | 无账户也能写，时间戳与保存状态可理解，首个恢复点自动建立 |
| 阅读历史 | 搜索或月历进入同一条目，返回保留列表位置和查询 |
| 导入 | 识别、预览、冲突、执行、结果；大任务有进度和取消 |
| 误删恢复 | 回收站可见，可恢复；永久清理明确说明结果 |
| 换机/卸载前 | 可创建外部备份并验证，不把应用内快照当外部保障 |
| 失败 | 草稿可取回，错误可诊断，失败状态有重试或导出入口 |

导航采用“今日、日历、日记、更多”，手机显示单列；平板宽度达到经过验证的断点后使用列表与阅读双栏。桌面重构阶段再加入快捷键与窗口菜单，手机不出现不可操作的鼠标提示。

## 4. 设计系统与组件规范

建立颜色、字阶、间距、圆角、边界、阴影、动效时长等设计变量。把“纸面”和“沉浸”表达为稳定的背景、排版和交互反馈，Android 上不模拟透明桌面窗口。

| 组件 | 功能契约 | 关键验证 |
|---|---|---|
| JournalEditorSurface | 文本、选区、会话、工具栏、保存反馈 | 中文输入、键盘遮挡、焦点恢复 |
| DiaryCard / Timeline | 摘要、日期、选中和操作菜单 | 虚拟化、长标题、TalkBack |
| MonthCalendar | 42 格日期、记录热度、选择 | 可点击尺寸、周起始设置、跨月逻辑 |
| ReadingSurface | 原文、搜索高亮、编辑入口 | 长文滚动、字体缩放、选取复制 |
| ImportStepper | 选择、预览、冲突和执行 | 取消、失败、超大数据分页 |
| SaveIndicator | 编辑中、草稿受保护、保存完成、失败 | 只由持久化结果驱动 |
| RecoveryCenter | 草稿、历史、回收站、备份 | 操作不互相覆盖，恢复后有结果 |

所有组件覆盖空、加载、成功、错误、禁用和恢复中状态。字体以系统默认为基线，可附带已授权字体；混合中英、日文、Emoji 和缺字回退要测量。支持 200% 字体缩放、TalkBack 和减少动画；手势必须有可见按钮替代。

开发早期制作组件展示页和截图基线，不把它作为用户功能发布。共享界面变化必须同时检查窄屏、宽屏、深浅主题和大字号。绘制的词云与图表必须提供同等信息的可访问列表，不能用一张 Canvas 代替语义结构。

## 5. 系统架构与模块边界

```text
Jot.Uno.Android（Skia）      未来 Jot.Uno.Desktop（Skia）
             │                         │
             └─ Jot.Presentation ──────┘
                DesignSystem / Features / Navigation
                           │
                    Jot.Application
                           │
                      Jot.Domain
                           │
                   Jot.Infrastructure
            Markdown / SQLite / Draft / Backup
                           │
            Android 文件、编辑器、声音、生命周期
```

`Presentation` 按 Editor、Library、Calendar、Insights、Import、Settings、Recovery 分功能组织；每个模块暴露状态、动作和导航结果。继续使用熟悉的 CommunityToolkit.Mvvm 即可，不为重构强行增加另一套状态框架。

领域与应用层不引用 Uno、WinUI、SkiaSharp 或 Android；平台能力通过 `IEditorAdapter`、`IExternalDocuments`、`IAppLifecycle`、`ISoundEffectService`、`IHapticService`、`IUiDispatcher` 注入。所有绘制对象只在呈现层，所有正文写入只经过应用保存用例。

建议目录为 `src/Jot.Domain`、`src/Jot.Application`、`src/Jot.Infrastructure`、`src/Jot.Presentation.Uno` 和 `src/Jot.UnoApp`。当前根目录 csproj 默认扫描子目录源文件，开始实施先隔离新增目录或独立迁移桌面工程路径，避免重复编译和资源冲突。

UI 类库按 Skia 目标和对应 Uno 配置编译，不直接加载只面向 Native renderer 的平台 UI 二进制。第三方图表/控件必须在 G0 核验对应渲染模式，不能只检查 NuGet 中是否有 Android TFM。[渲染器类库限制](https://platform.uno/docs/articles/features/using-skia-rendering.html)

## 6. 渲染与编辑器的具体实现

主要界面使用 Uno XAML 控件与 Skia 渲染，不为所有普通控件手写绘制。日历先采用规则网格；词云和复杂统计若有实际性能需要才使用 SKCanvasElement 等绘图入口，保留可访问语义层和命中区域。[Skia 绘图入口](https://platform.uno/docs/articles/controls/SKCanvasElement.html)

编辑器优先验证两条内部实现：Skia 路径的多行 TextBox、嵌入 Android 原生 EditText。G0 根据 IME、选区和长文结果只选一个作为首发主实现。由于编辑器关系数据完整性，允许 Android 采用原生输入控件；“统一界面”不承诺每个输入像素或系统菜单都相同。

Skia 可通过 ContentControl 承载 Android 原生 View，原生控件不会自动继承 Uno 样式，透明叠加、焦点和裁剪存在限制。正式界面避免在编辑器上叠加半透明纸纹或复杂变换，把纸面背景和工具栏放在可验证的独立区域。[原生嵌入说明](https://platform.uno/docs/articles/features/using-skia-hosting-native-controls.html)

`IEditorAdapter` 必须报告会话 ID、日期、文本版本、选区和组合输入状态。切换主题只更新样式，不能重建编辑器或重写正在输入的全文。文字变更、载入、撤销和恢复分别建模；组合输入结束才形成可靠的编辑事务，未提交的输入法候选不能承诺恢复。

时间戳在当前选区插入，撤销只由一层管理；历史采用增量/事务与内存预算，避免 200 个超大全文快照。切页和系统恢复从持久草稿重建，不从静态页面缓存推断未保存内容。

渲染优化按测量推进：列表虚拟化、词云结果缓存、热图局部更新、减少模糊与半透明层、不让光标或保存提示触发无关的大区域重绘。起步使用经验证的默认图形后端；Vulkan 等可选路径仅在性能收益和设备覆盖验证后启用，不作为发布必要条件。[可选 Vulkan 后端](https://platform.uno/docs/articles/features/using-vulkan-rendering.html)

## 7. 数据真源、草稿与恢复协议

用户正文仍为 UTF-8 Markdown；用本地日记日期作为逻辑键，不因旅行时区改变归档日期。记录相对路径、修订、父修订、内容哈希、UTC 修改时间和 schema 版本。绝对路径只是设备内部定位，不进入交换协议。

维护可重建索引和不可随意清理的状态库。状态库包含草稿、编辑序号、提交意图、导入批次和恢复记录。正文、状态、历史和 Trash 都在应用持久目录；音频解码、缩略图和导入暂存才进入可清理缓存。

修订元数据属于持久状态/旁车文件，并进入备份，不能只放可重建索引。哈希针对实际保存的 UTF-8 字节，换行/BOM 规范化必须明确选择。保存、导入、恢复和未来同步通过同一个按日期串行协调器；基线检查与提交不能被另一入口插入写操作。重建索引不会创建新的正文修订。

搜索建立按正文哈希增量更新的缓存，查询过期可取消；列表以日期游标分页。FTS 只有在实际 SQLite 构建与中文语义验证通过后采用。统计和词云按修订集合缓存，后台计算完成后发布不可变结果，UI 只更新受影响控件，避免全库读入与全树重绘叠加。

一次保存需要完成以下过程：固定日期及版本快照；草稿与意图事务落盘；检查基线；备份旧正文；同卷写临时文件并刷新；替换正文；更新索引与修订；完成意图。重启按哈希和意图恢复，重复执行不追加重复文本。不得把文件与 SQLite 声称为同一个原子事务。

界面区分“编辑中”“草稿已保护”“已保存”和“保存失败”。后一状态必须对应正文持久化成功，不能因为动画或音效播放完成就显示成功。保存期间有新版本时继续保持待保存状态；旧日期结果不能更新新日期。

草稿初始参数为 300～500ms 合并写，正文约 1.2s；后台事件只补充尽力提交。Android 可回收进程而不调用退出流程，必须依靠此前落盘状态恢复。[进程生命周期](https://developer.android.com/guide/components/activities/process-lifecycle)

磁盘满时保留最后完整正文并保护可保护的草稿，不清理旧恢复点来假装提交成功。用户主动清空内容需明确保存空正文或删除。异常恢复优先保证文本可导出，索引、统计和界面可退化。

## 8. 文件、导入、备份和同步扩展

首版采用应用私有工作库。SAF 选择器用于导入、外部备份和导出，URI 按流处理；权限被撤销时保留内部工作库并提示重新选择。不能让长期保存依赖某一个云文档提供者的可用性和重命名语义。[Android 文档访问](https://developer.android.com/training/data-storage/shared/documents-files)

导入复用日期规则，但工作台重新设计为可取消的批次。采用当前 20MB 单文件、100MB ZIP 总解包量作为初始边界，再限制条目数、路径、实际解包字节与时间；UI 分页展示预览，不一次构造所有大段正文控件。重复执行通过批次 ID 和条目结果判断，失败条目可重试。

备份为版本化 ZIP：manifest、哈希、正文、可选历史与草稿。写完并校验成功后记录外部备份成功；分享面板启动不等于备份完成。恢复先校验再预览，逐条提交且保留当前版本。原导出 Trim 行为需要绕开，新的备份提供原样保留测试。

应用内快照随卸载可能一并消失，外部备份是商用首版必需功能。测试权限失效、设备空间不足、损坏包、导入取消和换机恢复。[应用文件生命周期](https://developer.android.com/training/data-storage/app-specific)

后续自动同步放入应用层，不放入渲染层。设计持久队列、幂等 ID、版本基线、删除墓碑、冲突副本及远端条件写；断网不阻断本地编辑。正文和版本可交换，各端独立重建 SQLite。升级后兼容旧同步协议需要明确版本协商，不能用“同框架”替代协议兼容。

## 9. 平台能力、隐私与商业功能

原生声音服务使用 SoundPool 管理短素材，按需加载主题；App 退后台后暂停不必要反馈。音效与触感分别关闭，减少动态效果可禁用纸面动画。软键盘不保证逐键事件，声音跟随文本提交或明确保存动作。[SoundPool](https://developer.android.com/reference/android/media/SoundPool)、[KeyEvent](https://developer.android.com/reference/android/view/KeyEvent)

默认离线、无账户。系统备份和设备迁移对日记、状态库和密钥的处理需显式配置并验证；“本地优先”说明不能与 OS 自动上传行为矛盾。[Android 自动备份](https://developer.android.com/identity/data/autobackup)

诊断数据默认不包含正文、标题、文件名、搜索词或输入内容。用户可以预览诊断包再选择发送。应用锁、系统沙盒与应用层加密分别描述；增加加密时必须覆盖索引摘要、草稿、历史、缓存、导出和密钥恢复，不仅加密 Markdown 文件。

首版商业发行可以保持免费或采用付费下载；若需要内购主题或其他权益，建立独立 entitlement 服务并按渠道测试购买、恢复、退款和离线权益。不会因为权益校验失败而阻止已有日记读取和导出。账号、支付后台、端到端加密、客服平台等扩展需要单独成本。

设计资源、字体、声音和 NuGet/原生依赖记录许可证及来源；发行包附必要声明。真实用户数据不作为截图、性能样本和测试夹具，使用合成或获得授权的脱敏数据。

## 11. 商用验收与测量方法

Android 产品最低版本暂定 10，G0 后结合用户群调整。覆盖 4GB 中低端 ARM64、不同 GPU/OEM、当前目标系统和较旧支持系统；至少两种中文输入路径和 Gboard。系统字号、无障碍服务和省电策略纳入设备配置。

| 验收项 | 目标/通过条件 |
|---|---|
| 数据正确性 | 保存各阶段中断、索引损坏、权限失效、磁盘满后能恢复确认内容 |
| 编辑器 | 拼音、语音、Emoji、粘贴、选区替换、撤销、快速换日、旋转全部通过 |
| 原生嵌入 | 模态框、遮挡、裁剪、滚动、焦点、返回、200% 字号不出现阻断 |
| 渲染 | 参考机日记列表滚动目标 60fps；记录 P95 帧时间和严重卡顿，不只看平均值 |
| 输入/启动 | 100KB 文本输入反馈 P95≤50ms；冷启动可编辑 P95≤3.5s |
| 搜索 | 10000 篇已建索引数据，查询 P95≤500ms；初次建索引有进度与取消 |
| 长稳 | 连续写作 30 分钟、前后台 100 次、主题切换 100 次，无持续内存增长 |
| 无障碍 | TalkBack 可完成写作、读取热度、搜索、备份恢复，无只能手势触发的核心功能 |
| 兼容 | 桌面往返文本、旧备份、重复恢复、应用升级和格式升级均通过 |

数字是立项目标，不是当前已测结果。固定参考设备型号、数据集、Release 包和测量方法；初始基准不达标时先改实现或范围，不偷偷放宽门槛。1MB 单篇列为压力用例，保持全文完整并提供简化路径。

自动测试分为纯算法/用例、持久化故障注入、组件状态、截图基线和真机操作；截图不能替代语义与输入测试。所有核心自绘控件均要验证读屏和命中区域。框架及图形后端更新必须重跑输入、恢复和 GPU 设备矩阵。

## 12. 发布、运维与故障方案

持续集成锁定 .NET、Uno、SQLite、Skia 及全部传递依赖，构建可追溯 Release 包。启用裁剪或 AOT 是可测优化，不在没有完整回归时默认打开所有优化。检查实际原生库的 ARM64、16KB 页大小和 APK/AAB 安装；代码能编译不代表运行时二进制满足设备要求。[16KB 页大小](https://developer.android.com/guide/practices/page-sizes)

发行方确定应用 ID、签名持有者和渠道策略；版本号、versionCode、schema、提交哈希和包哈希关联记录。提交当日核验 target API、商店材料和权限说明，不把方案日期的规则当长期不变的配置。[Play target API](https://developer.android.com/google/play/requirements/target-sdk)

依次经过内部测试、封闭用户、少量发布、扩大范围。至少观察 7 天并记录有效样本量；出现数据错写、已确认草稿丢失或备份不可恢复立即暂停扩大。低风险视觉问题可关闭对应效果，数据问题不能靠禁用错误提示掩盖。

发布后维护 GPU/OEM/框架兼容台账。重大渲染故障优先提供原生编辑和导出入口；客服先保护数据，不直接要求清缓存中的持久状态或卸载。Android 修复通过更高 versionCode 包，数据库迁移保留恢复点，不假设可安装旧版降级。

月度检查依赖和漏洞；季度核对性能、Android 版本覆盖和升级计划。交付维护手册规定值班责任、错误码、数据恢复步骤和对用户的解释模板。诊断仅报告版本、耗时、错误码和能力，不上传日记内容。

## 13. 新 Windows 版本的可选实施路径

Android 正式发布并稳定后，创建独立 Skia Desktop 原型。使用复制的测试库导入，不直接连接正在由旧 WinUI 版使用的目录；迁移前备份，记录迁移版本，并处理旧进程仍在运行的情况。

Windows 专门验收窗口尺寸、标题栏、快捷键、鼠标侧键、剪贴板、中文 IME、字体、DPI、多显示器、文件锁和单实例行为。旧版的 Mica/Acrylic 效果是否保留属于产品选择，不能把外观差异作为缺陷隐藏。

新版先作为可选预览，两个应用不并发写同一个活动库。成熟后再提供一向迁移工具及可验证的导出返回路径；旧版何时停止维护由发行方另行决定。安装器、签名、更新通道和客服资料都要随新桌面产品重新验证。

## 14. 选型复核与最终交付

| 主要目标 | 更匹配的路线 | 主要代价 |
|---|---|---|
| 尽快交付可靠 Android 日记 | MAUI 原生控件 | 手机 UI 重写，桌面和手机分别维护界面 |
| 未来重用 Web 排版和编辑组件 | MAUI Blazor Hybrid | WebView、通信和前端安全维护 |
| 优先保留 WinUI 页面结构 | Uno 渐进迁移/Native | 控件兼容、平台分支、双端回归 |
| 建立长期统一品牌与组件体系 | 本方案 Uno Skia | 前期设计重构、原生嵌入与图形设备验证 |

本方案的完整交付包括设计变量与组件规范、原型取舍报告、架构与接口、数据格式、安装包、依赖锁与许可、自动测试、真机及 GPU 矩阵报告、备份恢复手册、迁移说明、发布和故障处置手册。验收由产品、技术、测试和发行角色共同完成；只有截图一致或应用能够启动，都不构成商用完成。
