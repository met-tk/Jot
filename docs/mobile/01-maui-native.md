# Jot Android 方案一：MAUI 原生控件与共享 C# 核心

文档版本：1.0｜编制日期：2026-10-16｜代码基线：`6d019b3`、Jot 1.2.1

本文是待实施方案，不代表已有 Android 实现或测试结论。性能数字是建议验收目标，工期是预算估算。目标为先交付 Android 手机商用版本，保留现有 Windows 版，后续可增加 iOS。

## 1. 决策摘要与适用条件

采用 .NET MAUI 的原生控件体系重建移动界面，复用 C# 业务算法和 Markdown 数据格式。以手机输入、可靠保存、备份恢复为首要交付目标。此方案适合维护者主要使用 C#、希望较快推出 Android、接受桌面和手机各有界面的情况。

四份方案是互斥的主路线，不应同时开发四个正式客户端。本方案是默认推荐路线；MAUI Blazor Hybrid 更适合有 Web 编辑器需求的团队，Uno 渐进路线更适合强调 WinUI 源码复用的团队，Uno Skia 路线更适合统一品牌界面。

MAUI 的 Android 支持不意味着 WinUI XAML 可以直接运行。新移动项目采用当前受支持的 .NET 10 / MAUI 10 服务版本，启动时锁定 SDK、workload 和 NuGet 依赖。MAUI 支持周期与 .NET 支持周期不同，年度升级应纳入维护预算。[MAUI 概览](https://learn.microsoft.com/en-us/dotnet/maui/what-is-maui?view=net-maui-10.0)、[MAUI 支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy/maui)

首次启动允许立即写作，也提供导入旧日记入口。导航采用“今日、日历、日记、更多”；写作页面保留日期、保存状态和时间戳工具栏。键盘弹起后正文光标与工具栏可见；返回操作先处理键盘，再处理页面导航。导入采用“选择来源—识别日期—处理冲突—确认—结果”五步流程。

首次完成日记后，在合适位置引导建立外部备份。私有目录数据会随卸载清除，不能把应用内快照称为卸载后的备份保障。[Android 应用文件说明](https://developer.android.com/training/data-storage/app-specific)

手机布局以 360dp 宽为基础，横屏和大字体不能遮挡保存、恢复等主要操作。按钮建议至少 48dp 可点击区域；热度同时显示数值，不能仅依赖颜色。支持 TalkBack、系统字体缩放、深浅主题和减少动态效果。系统返回、手势返回和外接键盘都进入同一个导航协调器。

## 4. 目标架构与依赖边界

```text
现有 Jot.Windows ─┐
                 ├─ Jot.Application ─ Jot.Domain
Jot.Mobile.Maui ──┘          │
                     Jot.Infrastructure
                  Markdown / SQLite / Backup
                            │
                   平台路径、流、音效、生命周期
```

建议最终目录为 `src/Jot.Domain`、`src/Jot.Application`、`src/Jot.Infrastructure`、`src/Jot.Mobile.Maui` 和桌面工程。Domain 包含日期、正文和算法；Application 包含用例与接口；Infrastructure 实现文件和 SQLite；平台项目只负责界面和系统能力。

现有根目录 `Journal.csproj` 使用 SDK 默认文件包含规则。新增子工程前，先在实施提交中隔离其源文件/XAML 扫描范围，或迁移旧工程目录；否则新工程中的 C# 文件可能被旧桌面工程再次编译。本文只增加方案文档，未进行这些工程修改。

开始阶段不必为每个接口建立新程序集。先让共享核心脱离 `Microsoft.UI`、`Windows.*`、窗口句柄和注册表，再按维护需要拆分。共享库可临时采用无平台限定的 `net8.0` 供现有桌面引用；正式桌面接入共享层时另行验证受支持的运行时和 Windows App SDK 组合，最终统一版本，不能无限期保留过渡目标。

| 接口/服务 | 责任与约束 |
|---|---|
| `IDiaryRepository` | 根据日记日期读取、保存、软删除，返回明确成功或失败结果 |

## 5. 数据模型与可靠保存

日记逻辑标识继续采用用户选择的本地日期，一日一篇。日期不能因为时区变化自动漂移；修改时间额外保存 UTC。建议元数据字段为 `EntryDate`、`RevisionId`、`ParentRevisionId`、`ContentHash`、`ModifiedAtUtc`、`SchemaVersion`，索引只保存相对路径。跨端导出不携带 Windows 的 FullPath。

数据目录区分为 `Journals/` 正文、`Backups/` 历史、`Trash/` 回收站、`journal_index.db` 可重建索引和 `journal_state.db` 草稿及未完成操作。状态库不能跟随“清理缓存”删除。

修订和恢复元数据保存在持久状态或版本化旁车文件，不能只放在可重建索引中。ContentHash 按实际落盘的 UTF-8 字节计算，导入的换行/BOM 是否保留由导入模式明确决定；索引重建不生成新内容修订。自动保存、导入、恢复和未来同步统一经过按日期串行的写入协调器，基线检查与提交在同一临界区，避免检查后被另一写入覆盖。

保存协议按以下顺序实现并进行故障注入：

1. 从编辑器获取不可变快照：日期、正文、选区、编辑序号、基线修订。
2. 将草稿及保存意图事务性写入状态库；只有成功后才显示“草稿已保护”。
3. 若基线修订已变化，保留当前草稿并产生冲突结果，不静默覆盖。
4. 为旧正文创建恢复点，在同一文件系统写临时文件并完成刷新，再替换目标正文。
5. 更新索引和修订记录，标记操作完成；文件与数据库不假装具备同一个事务。
6. 只有当前编辑序号仍等于提交序号时才清除未保存状态。保存期间新增的输入继续等待下一次提交。
7. 启动时检查未完成操作，通过哈希区分“正文已写但索引未更新”和“正文尚未写入”，幂等恢复。

草稿建议在输入变化后短间隔合并写入，初始调优值 300～500ms；正式正文保存可保留约 1.2s 防抖。将这些值作为可测参数，不能承诺任何突发断电场景零损失。恢复保证限定为已完成持久化确认的内容；仍在输入法候选区、尚未提交给应用的文本不在保证范围。

切后台时触发尽力提交，但不依赖退出事件提供最后一次保存。Android 可以直接回收进程。[生命周期说明](https://developer.android.com/guide/components/activities/process-lifecycle)

新保存协议不再把“全文清空”自动解释成无修改：已有日记清空必须允许保存空正文或走明确的删除确认。磁盘满、索引失败和快照失败要分别返回；用户看到的“已保存”必须对应正文成功提交。备份采用按日与按容量双限额，保存进行中不清理恢复所依赖的版本。

## 6. 编辑器、音频和移动交互实现

第一步使用 MAUI `Editor` 完成多行纯文本编辑。通过专用控件和 Handler 做 Android 定制，避免对所有 Editor 注册全局副作用。记录光标和选区，但不在每次 TextChanged 后把全文重新赋回控件，以免打断中文组合输入。[Editor](https://learn.microsoft.com/en-us/dotnet/maui/user-interface/controls/editor)、[Handler 定制](https://learn.microsoft.com/en-us/dotnet/maui/user-interface/handlers/customize)

撤销采用文本编辑事务，而不是无限保存全文副本。组合输入完成、粘贴、时间戳插入各形成独立事务；连续普通输入可以合并。由同一层拥有撤销历史，避免自定义与原生历史同时消费。切换日期前冻结旧会话，旧会话的迟到保存结果不得更新新日期界面。

验证 1KB、100KB、1MB 长文。超过已测交互上限的文件仍可完整导入和导出，但提供专门的大文件阅读/编辑提示，不截断内容。首版不做复杂富文本，不把 Markdown 标记转换成不可逆结构。

Android 短音效以 SoundPool 为候选实现，仅预加载当前主题。生成音频在构建期准备或写入可写缓存；不能沿用运行时写安装目录 Assets 的方式。后台暂停、音频焦点变化和静音设置需要处理。[SoundPool](https://developer.android.com/reference/android/media/SoundPool)

按键声根据文本提交和特定编辑动作触发，不能依赖软键盘逐键 KeyEvent。页面微动与设备触感分开配置，减少动态效果设置可关闭动画。[输入事件限制](https://developer.android.com/reference/android/view/KeyEvent)

## 7. 文件交换、备份与后续同步

系统文件选择通过 Storage Access Framework 获取 URI 和读取流。首版内部工作目录保持普通文件语义；外部文档用于导入、导出和备份，避免不同文档提供者的替换能力影响每次自动保存。[SAF 文档](https://developer.android.com/training/data-storage/shared/documents-files)

列表按日期游标分页，默认每批 50 条；搜索按输入序号取消过期请求。建立正文变更驱动的搜索缓存，只有哈希变化的条目需要更新。FTS 作为候选优化，先验证目标 SQLite 的扩展支持以及中文子串召回；否则使用经过基准验证的候选筛选与全文匹配。统计按日期/修订增量聚合，进入页面不重新加载全库正文。上述策略是达到搜索指标所需的新增工作。

复用现有日期识别和导入切分规则，同时移除对物理文件路径的强制要求。保留当前 20MB 单文件、100MB ZIP 解包总量作为初始防护上限，另加文件数量、实际解压字节数、超时和取消控制；不凭 ZIP 声明长度信任输入。保留原始导入来源直至用户确认结果。

备份格式建议为版本化 ZIP：`manifest.json`、正文、可选历史和可选草稿，manifest 保存格式版本、条目数量和文件哈希。验证路径穿越、重复日期、损坏条目和不支持版本。恢复先在暂存区完成校验，再预览冲突并逐项提交；恢复失败不清空已有库。恢复是复制行为，源备份保持不变。现有导出使用 Trim，正式备份应另走保留字节或明确规范化的路径，不能直接宣称原样无损。

商用 1.0 默认本地使用，不要求账户。后续自动同步另增变更日志、幂等操作 ID、版本/基线、删除墓碑和冲突分支；同步正文和元数据，不同步正在使用的 SQLite 文件。不能用设备修改时间决定谁覆盖谁。设备离线后重新上线必须测试“编辑/编辑”和“删除/编辑”冲突；冲突保留双方。自建账户服务、端到端加密和密钥恢复应分别预算。

## 8. 隐私、商业功能和支持边界

商用完成度不等于必须增加账户或订阅。建议首版以本地工具交付，是否收费是产品决策。若采用付费下载或应用内购买，应分别验证目标渠道的支付、恢复购买和退款状态；付费失败不得锁住用户已有正文及导出能力。

正文、标题、搜索词、文件名和剪贴板内容不得进入默认诊断日志。崩溃报告仅包含经过脱敏的错误码、版本和设备能力，上传为显式选择。离线版默认不主动连接业务服务器；Android 系统备份应显式配置，排除明文日记、草稿、索引和秘密，验证云备份及设备迁移两种行为，不只依赖单个 manifest 开关。

私有目录和应用锁不等于应用层加密。首版准确描述本地保护范围。若宣称加密日记，则正文、草稿、索引摘要、备份、临时文件都必须纳入加密设计，并验证密钥失效和换机恢复。SecureStorage 只适合小型密钥或令牌，不适合存整篇日记。[安全存储](https://learn.microsoft.com/en-us/dotnet/maui/platform-integration/storage/secure-storage?view=net-maui-10.0)

支持入口提供版本、错误码、存储剩余空间和用户可预览的诊断包；默认不收集正文。建立丢失数据、导入失败、购买异常三类工单处理流程。声音、字体、图标和第三方组件保存授权记录，随安装包提供必要许可信息。

## 10. 验证矩阵与发布门槛

测试设备至少覆盖 Android 10 起的产品最低版本、一个中间版本、当前目标版本；至少一台 4GB 内存中低端 ARM64 真机、两家 OEM、Gboard 与至少一种中文输入法。最低系统 Android 10 是产品建议，不是 MAUI 框架最低要求，G0 后依据用户群调整。

| 类型 | 核心验收 |
|---|---|
| 数据 | 在保存每个阶段杀进程、模拟磁盘满、损坏索引；已确认保存内容可恢复 |
| 编辑 | 组合输入、语音、Emoji、粘贴、撤销、快速换日、旋转、后台恢复 |
| 交换 | 桌面到 Android 再回桌面，日期和正文语义一致；保留模式按字节核对 |
| 导入 | 1000/10000 篇样本、重复导入、超限 ZIP、取消后重试、冲突覆盖恢复 |
| 性能 | 4GB 参考机冷启动可编辑 P95≤3s；100KB 文本输入反馈 P95≤50ms；10000 篇已建索引搜索 P95≤500ms |
| 长稳 | 连续写作 30 分钟、切页 100 次、导入取消 20 次，无持续内存增长 |
| 可访问性 | TalkBack 完成写作、保存、恢复；字体放大 200% 不遮挡关键操作 |
| 升级 | 上一公开版本升级到候选版、迁移失败重试、旧备份恢复，数据不重置 |

性能目标是待验证门槛；初始全量建索引不计入已建索引搜索指标，但必须展示进度并可取消。保存与恢复关键场景要求全通过，不用一般代码覆盖率代替。

CI 依次执行格式/依赖检查、核心测试、历史数据夹具、Android Release 打包、安装升级和设备冒烟。密钥保存在发布凭据系统，应用 ID、签名身份和递增 versionCode 提前固定；正式应用 ID 由发行方决定，不在方案中编造。

发布包必须核验实际 native SQLite、运行时及其他 .so 的 ARM64 和 16KB 页大小兼容，不能仅检查 C# 编译成功。Google Play 的 target API 和页大小政策在提交时重新核验，保存核验日期和实际构建版本。[target API 要求](https://developer.android.com/google/play/requirements/target-sdk)、[16KB 页大小](https://developer.android.com/guide/practices/page-sizes)

按内部测试、封闭测试、少量用户、扩大范围逐步交付。灰度停止触发条件包括任何确认的数据丢失、恢复失败或持续保存错误；其余稳定性建议观察至少 7 天并记录样本量。小样本无崩溃不应宣称已经达到统计可靠性。

## 11. 上线后维护与故障处置

发布包、依赖锁、混淆/符号文件、数据 schema、迁移脚本、测试报告和源码提交建立一一对应关系。月度检查框架、SQLite、Android SDK 和组件更新，重大升级先跑数据恢复与输入测试。

Android 回退通常应通过更高 versionCode 的修复包完成，不能依赖用户降级安装。数据迁移采用可重试步骤，迁移前建立恢复点；不兼容旧格式时保留导出通道，不能强行让旧程序打开新库。

遇到保存错误，先保护草稿并提供导出，再重建可恢复索引；不让客服建议用户先清数据或卸载。遇到同步类问题，未来同步模块应可停止远程写入而保留本地编辑。完成商用交付须同时交付发行操作手册、用户备份恢复说明、故障码表、依赖许可清单和维护责任人名单。
